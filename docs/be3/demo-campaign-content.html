Kịch bản demo

Chạy một campaign test

Demo nhanh bằng Test URL của webhook và một campaign đã tồn tại trong cùng Supabase project mà Python API đang dùng.

Khởi động Python API

Trong PowerShell ở thư mục repo, chạy:

Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\.venv\Scripts\Activate.ps1
Set-Location services\llm-service
python -m uvicorn rag_api:app --host 0.0.0.0 --port 8000

Mở http://localhost:8000/health, cần thấy status ok. Tạo services/llm-service/.env từ file mẫu và điền thông tin Supabase test cùng hai API key riêng.

Mở n8n & kiểm tra kết nối

Mở http://localhost:5678, chọn workflow Campaign Content. Kiểm tra Gemini credential, Header Auth cho RAG_API_KEY và credential riêng cho CONTENTS_API_KEY. n8n Docker gọi API trên máy Windows qua http://host.docker.internal:8000.

Lắng nghe Test Webhook

Trong Webhook node chọn Test URL và bấm Listen for test event / Execute workflow. Thay UUID mẫu dưới đây bằng campaign test đang có thật trong cùng database:

$payload = @{
  type = "INSERT"
  table = "campaigns"
  schema = "public"
  record = @{ id = "<EXISTING_TEST_CAMPAIGN_UUID>" }
  old_record = $null
} | ConvertTo-Json -Depth 8

Invoke-RestMethod -Method Post -Uri "http://localhost:5678/webhook-test/supabase-campaign-created-content-test" -ContentType "application/json" -Body $payload

Đường dẫn webhook phải khớp Path trong node. Test URL chỉ hoạt động trong lúc n8n đang lắng nghe.

Chạy persona & theo dõi execution

Chọn persona trong Set Persona, chạy workflow, rồi mở tab Executions. Nếu nghiệm thu đủ persona, chạy lần lượt cả bốn persona và lưu lại execution ID của từng lượt.

Kiểm tra API, database và FE

Xác nhận mapper có 10 records; HTTP response có inserted_count: 10 và 10 content IDs. Truy vấn public.contents theo campaign/persona, rồi tải lại trang cộng tác viên để xem các dòng approved.

TEST URL · chạy có kiểm soát

POST payload vào Webhook

Dùng khi cần quan sát một execution với campaign có sẵn. Không cần tạo campaign mới; chỉ gửi sau khi n8n bắt đầu lắng nghe.

PRODUCTION URL · demo tích hợp

Tạo campaign từ FE

Bật workflow và xác nhận Supabase trigger trỏ tới URL Production. Tạo campaign test trên FE rồi kiểm tra execution mới xuất hiện trong n8n.

Supabase Cloud không gọi được localhost. Nếu n8n chạy local, cần HTTPS tunnel Cloudflare và cập nhật URL production đầy đủ trong cấu hình webhook. Quick Tunnel có thể đổi URL khi khởi động lại.

Tiêu chí demo thành công

Checklist nghiệm thu nhanh

  • Execution chạy qua enrich → LLM/parser → validator → mapper → /contents/batch.
  • Batch có đúng 10 dòng cho một persona; 5 dòng đầu đủ bộ, 5 dòng sau chỉ có hook theo handoff BE2.
  • API trả inserted_count: 10, 10 content IDs, status và flags.
  • FE hiển thị rows có status = approved (lowercase).
  • Ghi lại campaign UUID, persona và execution ID để Tester 2/FE kiểm tra.
Về status: API tự chạy guardrails cho giá, mã khuyến mãi và claim. Nếu database còn trigger auto-approve tạm của BE1, status approved có thể do trigger ghi đè; cần nêu rõ điều đó khi trình bày.

Còn cần xác nhận

Không nhầm bằng chứng demo

Các mục BE2 ghi nhận còn thiếu
  • workflow_campaign_content.json đã được thêm từ export người dùng gửi và đã scan secret. Execution #223 đã succeeded theo ảnh; cần lưu raw output/response API gắn với lần chạy.
  • Structured Output Parser chưa nối vào Basic LLM Chain; cần BE2 xác nhận validator Code hiện tại có thể thay thế hay phải nối parser và chạy lại.
  • Cần lưu raw output/response API và đối chiếu chúng với execution #223 cùng 10 dòng trong Supabase.
  • src/lib/database.types.ts chưa có trường generation_key.
  • Migration có trong repo nhưng chưa có bằng chứng đã apply vào Supabase.
  • Chưa có Tester 2 acceptance.
Workflow JSON đã có trong repo chưa?

Đã có services/llm-service/workflow_campaign_content.json, lấy từ export do người dùng cung cấp. Giá trị secret và n8n instanceId không có trong file; credential references vẫn được giữ và cần gán lại nếu import vào instance khác.

Retry/idempotency đã kiểm tra live chưa?

Code dùng generation_key để upsert tránh trùng, nhưng cần xác nhận migration unique index đã apply vào đúng project và chạy retry trên Supabase thật. Unit test mock không phải bằng chứng live.

Workflow không chạy từ Cloud thì sao?

Kiểm tra Production URL và trạng thái tunnel Cloudflare; URL public cần đúng path Webhook, không chỉ domain gốc. Với n8n Docker gọi Python trên cùng máy, dùng host.docker.internal.
